# Learned categorisation — evaluation

Generated by `python tools/evaluate_model.py` on 2026-10-17. **Synthetic data only** (privacy rule): invented merchants whose names carry category words, plus ~10 % deliberately ambiguous names. Real-statement accuracy will differ; the app's *Settings → Smart categories* tab reports the score on your own data.

## Method

- Features: TF-IDF word 1–2-grams + character 3–5-grams of the cleaned narration (digits and payment-channel words removed) + a debit/credit marker.
- Domain constraint: debits only get expense/transfer categories, credits only income/transfer.
- **Merchant-grouped split** (75 / 25): no merchant is in both train and test, so every test row is a merchant the model has **never seen**.

All three are close in accuracy; Complement Naive Bayes labels the most rows at the default threshold with comparable accuracy and is the fastest, so the app uses it.

## Main benchmark (seed 7)

- Training: 446 transactions from 116 merchants; test: 150 transactions from 38 **other** merchants (shared merchants: 0).
- Accuracy (always guessing): **77.3 %**; macro-F1 0.743.
- At the default threshold 0.60: labels **78.7 %** of rows, **98.3 %** of them correct; the rest stay Uncategorised for the user.

### Why it gets some wrong

| Test merchants whose category word… | Correct | Accuracy |
|---|---|---|
| known word | 116 / 116 | 100.0 % |
| new word | 0 / 26 | 0.0 % |
| ambiguous | 0 / 8 | 0.0 % |

When the category word was seen in training the model is almost always right; the errors are words it has never seen (no model can know a new word's meaning without an example — one manual correction teaches it) and deliberately ambiguous names. Some words are shared between categories (TRAVELS: cabs vs tours), which is realistic.
